## 统一教案模板(讲稿版)

每个课时都按以下 9 节组织,**讲师可直接照搬**:

1. **基本信息**:课时编号 / 时长 / 课型 / 前置 / 教具。
2. **教学目标**:知识 / 能力 / 素养(三类目标)。
3. **教学重点与难点**。
4. **教学准备**:教具、环境、提前发放材料。
5. **教学过程**:**分钟级时间分配 + 完整讲师讲稿 + 互动话术 + 板书要点**。
   - 每个知识点都有"是什么 → 为什么 → 怎么用 → 易错点"四段式讲解。
   - 关键概念配可直接念的口述内容(`> 【讲师讲稿】` 块)。
   - 重要演示给出"反面代码 + 现象 + 修复"的对照。
6. **板书设计**:核心图/公式/代码骨架。
7. **课堂练习**:讲师在课堂上推进的小型练习。
8. **测查题与参考答案**:5 道题(3 选择 + 1 简答 + 1 编程/场景)及详解。
9. **教学反思要点**:课后讲师自填,供后续迭代。

## 使用建议

### 给讲师
1. 备课时按本目录的教案走,蓝色引用块可直接念出来给学员。
2. 提前准备每节的"教具"与"故障注入样本"。
3. "教学反思要点"在每节课后填,作为下一轮课程优化依据。
4. 综合实战(L12 / L18 / L22 / L36)是 4 个里程碑,务必给足时间。
5. 如发现某段讲稿口语化不足,鼓励改写成你自己的语言;讲稿是脚本,不是枷锁。

### 给学员
1. 主要看 `../outline/36-lessons-outline.md`,本目录的板书与练习帮你预习/复习。
2. 课后认真做"作业"和测查题,对答案。
3. 把综合实战的代码提交到自己的 GitHub,形成作品集。

### 给团队负责人
1. 用本目录评估讲师备课质量、统一教学风格。
2. 把"测查题"作为课程留存抽测题库。
3. 综合实战的评分表(L36)可作为团队内部评级参考。
